# Test090：掉线恢复与接收状态定位

这版修复三个已在代码中确认的问题。是否能消除实机掉线和发送超时，需要加载新驱动后验证；AirDrop 仍未实现。

| 改动 | 之前的问题 | 本次处理 |
| --- | --- | --- |
| Wi-Fi 链路状态 | 关联断开会同时清除 BSD 接口的 `IFF_UP` | Tahoe 只清除 `IFF_RUNNING`，保留接口开启状态；首次连接路径不变 |
| STA 管理队列清理 | 固件返回管理 TID 15，旧代码因超出 host TID 数组而跳过 | 仅接受 STA 的固定管理队列，并核对回收位置没有越过已提交范围 |
| CCMP 密钥提交 | 命令入队前被拒绝返回 `EBUSY`，上层会把它当成已接受的异步请求 | 仅在 Tahoe 硬件 CCMP 路径转成 `EAGAIN`，其余错误、软件加密及旧系统路径保持 |

队列读写序号按固件的 16 位约定处理，再换算成 ring 下标。不能把 1024 项 ring 的大小当成写入序号的上限。

密钥改动会进入原有认证失败和重连流程，不会自动重试。它也不回滚上层已经写入的 host key 缓存；清理完成前相同密钥重试的处理仍需单独核验。未修改 replay 检查或防止密钥重复安装的逻辑。

## 验证范围

离线测试直接提取生产函数，覆盖管理 TID、STA/P2P 队列归属、环形回收边界、写序号回绕、CCMP 返回值以及 BSD 接口标志。通过这些测试只说明相关代码路径符合约定，不证明固件已完成发送或手机已收到数据。

重启后先复验普通联网、持续运行与掉线恢复，再进行有界接收诊断。原生 `awdl0` 数据收件、IPv6 对端应答和双向 AirDrop 分别验收。

本候选的 12 组针对性测试、Release 构建、编译配置检查和签名验证已通过。额外检查发现 `test075_tx_ring_capacity.py` 的 BA 测试夹具缺少声明；在未修改的 `afb6b0c` 基线上同样失败，本版没有改 BA 路径。

固定 36 字节固件快照在独立分支开发。本轮审查发现 NIC 清理失败后的锁计数问题，因此没有加入 Test090 实机候选。

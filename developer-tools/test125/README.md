# Test125：等待发送完成，再安全收尾

Test124 已收到一个与请求标记匹配的原生 `awdl0` UDP 回包。驱动接收收据也记录了一帧捕获、解码和成功 `ifnet_input`。但 helper 最后以 `ETIMEDOUT` 退出，发送完成和资源释放没有通过；这不是 AirDrop 成功。

本版只修复紧邻的两处问题：

- 驻留窗口 END 之后，在原有 350 ms 等待预算内接纳同一发送槽的精确 TX_RSP。END 仍撤销 RX 租约，不续期、不重发；超时、身份变化或隔离继续走失败路径，不释放未知 DMA。
- OpenWrt 恢复 AP 时，`ubus up` 最多尝试三次，保存并输出首个错误。成功后仍验证原 AP、另一频段和配置；失败时保留恢复 watchdog。

本轮诊断在驻留 START 前被拒绝：驱动当前代次为 5，已发布的 MCC 频道许可记录仍为 3，内核返回 `EOPNOTSUPP`。原生 UDP 未发出，因此没有测到本版的发送完成等待修补，也没有新的回包或 AirDrop 结果。路由器恢复返回 0，四项配置哈希不变，临时接口和 guard 已清；驱动复位计数未增加。联网冒烟和睡眠按要求跳过。

已定位周期性 MCC 发布从独立 watchdog 工作队列调用，而发布函数要求主 gate，导致直接返回。后续源码已改为非阻塞进入主 gate，沿用生命周期锁，不改真实响应代次或发射准入。离线回归和启用配置编译通过；该修补没有写入 EFI，不属于当前运行二进制。初始化 GET_CURRENT 与 CHUB 通知的证据仍分开处理。

`coordinate_directed_test125.py` 复用原有有界执行器和未变更的 Test124 对端程序，保留其架构、协议与源码哈希验证。本轮结束后补齐独立的目标系统增量审查收据：继承 Test124 有限范围的 25G416 ABI 审核，绑定 Test125 构建、部署与生产差异，不改原构建收据，不宣称全部私有 ABI 或运行时兼容已通过。

# Test099

本轮处理两件事：发送完成时读取了错误槽位的信息，以及测试包可能早于 149 频道接收窗口发出。

## 发送与密钥更新

- 回收边界仍使用固件返回的 exclusive SSN；只有回收区间内存在唯一有效槽位时，才使用该槽位的帧类型、节点与速率信息。
- 完成记录升级为 schema 3。完整的单槽扫描即使与响应帧头不匹配，也保留原始 TX_CMD 的 FC/SC。
- bit 30 表示看到了单槽命令头；bit 29 仍表示严格匹配。两者都不能单独证明 AP 已确认 Group2。
- `collect_rekey099.py` 需要本次构建的 `--expected-uuid`，分别保留完整快照和实时计数。只收集数字状态，不导出密钥。

## 原生 awdl0 接收

100 ms、149 频道的接收配置不变。新增 live START 快照，把 run token、owner、代次和截止时间一起发布；只有确认命令成功且已 START 的新快照，才能放行诊断发送。停止、结束、复位或身份不匹配后，旧快照不可继续放行。

`NATIVE_ARMED` 只代表诊断请求被接受。`NATIVE_RX_READY` 只代表本地接收窗口准备好；真实数据帧、awdl0 输入和接收端收件仍分别验证。

默认工具只规划或检查。实际诊断使用本次构建与部署回执生成的私有入口，重启后再执行。Wi-Fi 基线、密钥更新和用户开关测试分窗记录，睡眠按用户要求跳过。

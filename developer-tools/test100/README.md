# Test100

本轮核对两端的数据入口：OpenWrt 的发送回显来自哪里，Intel 最早收到的描述符是什么。同时把密钥回复的提交身份和发送完成记录放在一起。

## 发送与密钥更新

- 回收边界仍使用固件返回的 exclusive SSN；只有回收区间内存在唯一有效槽位时，才使用该槽位的帧类型、节点与速率信息。
- 完成记录升级为 schema 4。在原有锁和有界遍历内，复制对应槽位的 host cookie、代次和提交帧头；找不到、过期或有多个候选时分别记录。
- bit 30 表示看到了单槽命令头；bit 29 仍表示严格匹配。两者都不能单独证明 AP 已确认 Group2。
- `collect_rekey100.py` 需要本次构建的 `--expected-uuid`，分别保留完整快照和实时计数。只收集数字状态，不导出密钥。

## 原生 awdl0 接收

100 ms、149 频道的接收配置不变，沿用 Test099 的 live START 门禁。ROC 记录升级为 schema 3，保留通知的 len_n_flags、RXQ/RSS/RPA，以及有效描述符中的 filter_match、mac_context 和来源 STA。缺失字段明确标为未知；这些字段不改变接收规则。

RXQ 是通知中的原始字段，不等于主机 ring 编号；mac_context 是原始掩码，不证明 PHY1 归属。来源 STA 的 found 位为真时，ID 0 也可以是有效值。

`NATIVE_ARMED` 只代表诊断请求被接受。`NATIVE_RX_READY` 只代表本地接收窗口准备好；真实数据帧、awdl0 输入和接收端收件仍分别验证。

默认工具只规划或检查。实际诊断使用本次构建与部署回执生成的私有入口，重启后再执行。Wi-Fi 基线、密钥更新和用户开关测试分窗记录，睡眠按用户要求跳过。

## 尚未确认

Test099 启动初段的无人操作断链仍未解释，不能仅凭帧头差异归因于密钥更新。Test100 的离线测试不能证明掉线已修复。当前配置仍关闭主机 AWDL 发送，原生 awdl0 回包和双向 AirDrop 尚未通过。

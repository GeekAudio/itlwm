# 开发验证

40 项验收沿用固定编号。每条证据保留版本、启动、窗口、采集结果和原始文件哈希；新窗口追加记录。新版没有复测时显示“待复验”，历史记录保留；出现反证时单独标记回归及其证据。

页面并列显示“历史曾验收”和“本轮复验”。历史覆盖率不代表项目完成率，也不表示这些能力在同一个版本同时通过。

## 按依赖合并测试

| 层 | 验收项 | 一次启动内的采集方式 |
| --- | --- | --- |
| 基础连接与接口 | 1-1～1-5、6-1～6-4、7-1 | 加载身份、接口、IPv6、链路状态与绑定 en1 的网络请求；长观察独立计时 |
| 固件资源与时序 | 2-1～2-5、3-1～3-5 | 同一有界 session 同步记录创建、驻留、队列和完整回收 |
| AWDL 控制面 | 4-1～4-4、5-1～5-2 | 与资源窗口合并，关联 PSF/MIF、对端身份、接纳时间和外部抓包 |
| 无线数据通路 | 4-5、5-3～5-5、6-5 | 对齐发送票据、空口帧、对端回应和 RX→ifnet；不能用本机完成代替收件 |
| IPv6 与服务 | 7-2～7-5 | 有效邻居、独立 ICMPv6 数据探针、mDNS/Bonjour 应答及分享握手 |
| 文件传输 | 8-1～8-5 | 双向实际收件、重复/大文件校验、最后做睡眠与共存复验 |

基础快照、被动日志和长观察可在同一次启动运行多个有界窗口。一次主动窗口同时采集驱动、接口与旁路证据，避免拆成多次重启。开关和睡眠测试放在需要稳定 epoch 的无线实验之后。

## 重复试验条件

没有新证据时，不重复相同实验。有新证据时，记录改变的条件、下一窗口要排除的假设和结束条件。

Test078 的固件探针仍把 `MAC_ADD` 尝试状态跨 reset 保留。命令回执不明可能意味着固件已经执行，需要隔离；主机端清除 claim 不能恢复这个固件状态。

后续允许同启动重试需要两类明确终态：

- 尚未 arm：持久化收据证明没有调用 arm，没有未知退出或发送，再建立新的 session。
- 已经 arm：新 session/generation、迟到通知隔离、队列及 DMA 完整回收均有证据；ACK 不明、超时或 reset 进入隔离。

当前 Test078 不具备第二类重开协议。被动窗口不消耗主动窗口；不得通过删除旧 claim 模拟固件资源已回收。

## 下一轮重点

- Test078 已含 current-AW 的实际 planner 时间、fallback 标志以及修正的协调器最终摘要。
- 当前实验发送准入只接受 AirDrop mDNS QM；独立 ICMPv6 需要专门的准入和发送窗口，先确认对端 AWDL 地址，再以小包数验证 Echo Reply。
- OpenWrt monitor 跟随所选 PHY 的频道。固定频道需读回核对；更长抓包仍需包数预算、窗口覆盖和 Mac/路由器时钟锚点，不能仅凭时间戳相似关联。
- 发送 watchdog 使用独立长窗口，保存关联/IP/状态迁移、reset/watchdog 计数和日志锚点。出现断链或错误时记录异常，不把其他干净窗口外推成长稳。

`test078/` 保存本轮主机工具源码及哈希。私有运行记录、系统分析映像和凭据不随源码分发。

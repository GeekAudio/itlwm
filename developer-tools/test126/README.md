# Test126：恢复同代频道许可

Test125 已正常加载，但单包诊断停在驻留 START 前：驱动已到新代次，频道许可发布记录仍是旧代，原生 UDP 没有发出。因此 Test125 的发送完成等待修补尚未获得实机验证。

本版合入两部分修复：

- 周期性 MCC 快照通过非阻塞主 command gate 发布，保留生命周期锁和真实固件代次。
- 将初始化 GET_CURRENT 与 CHUB 通知分开验证。初始化路径只接受实际成功、已应用的完整 51 项频道表和有效监管来源；空表、默认来源、世界域、错误状态或被动频道继续拒绝。

来源、请求序号、固件代次和通知代际绑定同一轮驻留，贯穿 START、发送前检查、RX 租约和队列交付。复位、新请求或新通知使旧许可失效；不把初始化请求冒充 CHUB 通知。Swift 采集器同步要求新字段，缺失或中途变化就停止。

仍只使用原有频道 6 的有界单包流程，保留 Test125 的发送完成等待及安全清理修补。没有放开频道 149 发射，也没有增加自动重试或持续无线发送。

候选已完成启用配置的编译和严格签名。部署与实机结果以里程碑页为准；构建通过不代表原生回包或 AirDrop 已通。联网冒烟和睡眠继续跳过。

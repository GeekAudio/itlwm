A · iPhone → Intel → macOS：接收方向

发现/触发与 AWDL 802.11 数据路径分层显示，最后落到 AirDrop 文件收件。

INBOUND · RX
01iPhone BLE 发现 / 触发发现附近设备并启动后续连接协商

职责：提供邻近设备发现或唤起入口；后续 AWDL 会话和数据包仍需单独建立并验证。

证据边界：BLE 可见或触发成功，不等于 Intel 收到 AWDL 控制帧，更不等于收到文件数据。

02AWDL 802.11 控制 / 数据邻居同步、服务会话及数据帧走无线链路

职责：Apple 无线直连协议的控制与数据交换在 802.11 空口承载；控制帧、管理 Beacon 与数据帧是不同证据类型。

验收：需要识别真实 AWDL 帧并建立发送端、频道、时钟和 Intel RX 观察的逐帧对应。

03Intel 固件 / 149 RX固件调度 PHY、过滤并产生接收通知

职责：固件与无线硬件接收并分类帧，主机侧需确认通知、PHY/频道和 descriptor 的对应关系。

验收边界：把频道驻留 START/END、管理帧和 AWDL 数据帧分开记录；驻留 ACK 或看到管理帧都不能证明 Intel 主机收到 AWDL 数据。当前候选结果见上方状态卡和本轮矩阵。

04DMA completionRX 环完成项指向可读的接收描述符

职责：中断/完成通知到达后，驱动按 DMA 映射和 ring 状态读取描述符。

验收：completion、主机映射生命周期和同一条记录身份都需闭合。观测到 RBID 或 raw 字节本身不证明 DMA 所有权、内容新鲜度或缓冲区安全。

完成通知交给主机 RX 软件路径；仍需逐层校验，不会自动进入网络接口
05RX_MPDU 解析 / 校验解码通知、descriptor、长度、状态与 PHY 元数据

职责：区分 descriptor 版本，验证长度、状态、频道/PHY 归属，再识别管理帧、控制帧或数据帧。

验收：必须把接收通知与同一 descriptor/ring slot 对上；候选字节或管理帧不能代替 AWDL 数据帧。

查看阶段 4 · AWDL 接收

06Owner / 数据门禁 / 解封装核对归属、频道、地址与长度，再解析并交付 IPv6

职责：核对 RX owner、频道、源/目的地址和长度；依数据帧契约去掉 802.11、LLC/SNAP 与 AWDL 头，并把 IPv6 交给 awdl0。

边界：当前解码器拒绝 protected frames。STA 密钥更新属于普通 Wi‑Fi 链路，不是 AWDL 数据门禁；AirDrop 应用数据的保密由会话层 TLS 提供。

验收：逐项证明门禁与解封装；软件路径存在不代表 descriptor 已获准或数据已交付。

07原生 awdl0 / ifnet解封后的网络帧进入 macOS 原生接口

职责：把接纳的数据帧交给 BSD/网络接口输入路径，使本机协议栈能真实消费数据。

验收：需有对应包的 ifnet 入站或受控接收回执；接口 UP/RUNNING 只说明接口状态。

查看阶段 6 · 原生 awdl0

08IPv6 邻居 / mDNS / TCP / TLS发现分享服务并建立加密应用会话

职责：IPv6 邻居可达并通过 mDNS 发现服务后，AirDrop 在用户选择对端时建立 TCP/TLS 会话并交换身份凭据。

验收：分别记录邻居、mDNS 应答、TCP/TLS 会话和真实文件收件；链路本地 IPv6 或服务发现本身不表示传输成功。

查看阶段 7 · IPv6 与服务发现 · Apple Platform Security · AirDrop security

09AirDrop 文件收件应用层完成校验、接收并保存文件

最终验收：在 iPhone 与 Mac 两个方向都完成真实文件收发，保留接收端文件和会话结果作为证据。

证据边界：以当前候选的第 8 阶段状态为准；链路就绪、邻居发现或 listener ready 不能替代文件收件。

B · Mac → iPhone：反向发送方向

从系统分享会话开始，经过原生接口和 Intel TX 路径，最终以对端实际收件闭环。

OUTBOUND · TX
01Mac 选择文件 / 分享会话应用层形成待发送文件和对端会话

职责：AirDrop UI 和系统分享服务完成文件选择、会话建立及发送数据准备。

验收：用户界面显示可选设备不表示文件已交给网络接口。

02网络栈 → native awdl0应用数据封装后交由 AWDL 网络接口发送

验收：需要从原生接口和 BSD 输出队列确认目标数据确实被接纳。

边界：本地 send 返回、接口计数或队列入队都不证明固件发射或对端收到。

查看阶段 6 · 原生 awdl0

03Owner / admission / TX 队列选定 AWDL owner、队列和可发送时隙

职责：验证当前 owner、频道/时隙、队列资源和 DMA 描述符归属。

验收：追踪提交、固件完成、实际空口发送与对端回执；只看到本地返回值不能跳过后续门槛。

查看阶段 5 · AWDL 发送

04Intel 固件 / DMA TX驱动提交后由固件调度并完成无线发送

验收：区分描述符提交、TX completion 和空口发射；completion 只说明固件报告了相应结果。

证据边界：以当前候选的本轮矩阵为准；本地 TX completion 不等于 iPhone 收到或保存文件。

05AWDL 802.11 → iPhone 保存对端接收、校验并完成文件落盘

最终验收：用 iPhone 实际收到并打开 Mac 发出的文件证明发送方向闭环，再反向传回文件。

边界：旁路抓包、Intel 本地完成通知和对端 AirDrop 文件结果是不同证据级别。

C · 常规 Wi-Fi STA 与 AWDL 共用 Intel 无线硬件

互联网链路和直连链路是两条逻辑路径；电源、固件调度和射频资源来自同一设备。

PARALLEL LOGICAL PATHS
Wi-Fi 路由器 / AP家庭或办公网络侧
⇄
Intel 无线芯片 / 固件STA + AWDL 共用设备；按电源与无线调度运行
⇄
en1 / IP 网络网关、DNS、HTTPS 等常规 STA 流量

STA 联网成功可作为常规 Wi-Fi 证据；它不代替 AWDL 的接收、awdl0 入站或 AirDrop 验收。两条路径共用芯片资源，切换、频道驻留、固件状态和电源生命周期可能相互影响。
